   + find . -type f \( -iregex '.*\.ttf$' -o -iregex '.*\.otf$' -o -iregex '.*\.woff$' -o -iregex '.*\.woff2$
   ' -o -iregex '.*\.eot$' -o -iregex '.*\.sfd$' -o -iregex '.*\.pfb$' -o -iregex '.*\.dfont$' \) -exec cp {}   ~/Desktop/000-TEST/font_search_server/ \;

   + searching current dir for a directory with text matching first arg passed to a script
   + find . -type d -maxdepth 2 -iname "*$1*"

   + find files newer - or older + than N days. Use just number for exact times.
   + find [path] -type f -mtime [+-]N
   
   + same as above, in seconds
   + find [path] -type f -mmin [+-]N
   
   + find files accessed (read/opened) N days
   + find . -type f -atime [+-]N
   + find . -type f -amin [+-]N
   
   + find files whose metadata (permissions/ownership) changed N days/minutes ago
   + find . -type f -ctime [+-]N
   + find . -type f -cmin [+-]N
   
   + find files newer than reference file or timestamp
   + find . -newer [reference_file]
   
   + as above but with timestamps, worth looking into how these work
   + find . -newer[acm]t "YYYY-MM-DD HH:MM:SS"
   
   + mixing time options for specificity
   + find . -mtime -2 -atime +7
   + find . -ctime 0 -mmin +60

   + using find to search by file size
   c = bytes, b = 512 byte blocks, k = kilobytes, M = megabytes, G = gigabytes
   + find . -size [+-]n[cwbkMG]

   + using exec to interact with return values
   the {} will be the file path returned by find, expanded into text.
   Must terminate with \; 
   + find . -type f -exec {} \;
   + find . -type f -exec cp {} /target/dir \;
   + find . -type f -exec stat {} \; 
   + find . -type f -atime -1 -size -10M -exec stat -f "%z %N" {} \;

++ networking
> sockets
   + software structure within a network node of a computer network 
   + endpoint for sending and receiving data across the network
   + defined by an API for the networking architecture
   + created during the lifetime of a process of an application running in the node
   
   + network socket / internet socket - externally identified by its socket address
   a combination of the transport protocol, IP address, and port number
   
   + socket is analagous to an electrical female connector 
   + port is used for external physical endpoints at a node or device 
   
   + ports, another communication endpoint. Within an operating system, a port is a logical
   construct that identifies a specific process or type of network service.
      - a port number is a combination of an IP address and transport protocol. 16-bit unsigned integer.
   + most common transport protocols are: 
      - Transmission Control Protocol (TCP)
      - User Datagram Protocol (UDP)
   + The port completes the destination and origin addresses of a message within a host to 
   point to an operating system process. 
   + Specific ports are reserved for well known processes. 
      - Ports below 1024 are known as well-known port numbers
      - Ports above 1024 are known as ephemeral port numbers
   + Ports provide multiplexing service for multiple services or multiple communication sessions at one 
   network address. In the client-server model of application architecture, multiple simultaneous 
   communication sessions may be initiated for the same service. 

   

   + an API for the network protocol stack creates handles for each socket created by an application
   often called a socket descriptor. In UNIX, this is a type of file descriptor. It is stored by the 
   application process for use with every read and write operation on the communication channel
   
   + once an API creates the network socket, it is bound to a type of network protocol,
   network address, and port number. 

> node 
   + redistribution point or communication endpoint within telecommunication networks
   + a physical node is a device capable of creating, receiving, or transmitting information
   over a communication channel
   + includes data communication equipment (modem, hub, bridge, switch) or data terminal
   equipment (digital telephone set, printer, host computer)
   + different from a passive distribution point such as distribution frame or patch panel
   +

++ Signals
> sigaction
   + system defined set of signals that can be delivered to a process. 
   + resembles a hardware interrupt, the signal is blocked from reoccurring, the current process context is saved, and a new one is built.
   + processes can specify a handler to which a signal is delivered, or if the signal is to be ignored. Handlers respond to given signals. 
   + processes can also specify a default process to use when a signal is delivered.
   + a process can block a given signal, in which case the delivery of the signal is delayed until the signal is unblocked
   + the action taken is determined on delivery.
   
   + Normally signals are handled on the current stack of the process, this can change on a per handler basis, so signals are handled
   in a special signal stack. 
   + signal routines normally start with their invoker blocked, but other signals may occur. 
   + a Global Signal Mask defines the set of signals currently blocked from delivery to a process. 
   + the Signal mask for a process is normally initialized from that of its parent, typically empty. 
   + the default Signal Mask can be altered with sigprocmask calls, or when a signal is delivered to the process. 
   
   + when a Signal Condition arises for a process, the signal is added to a set of signals pending for the process. 
   + if a signal is not currently blocked by the process, then it is delivered to the process. 
   + a signal can be delivered at any time to a process that has entered the operating system. 
   +

++ Shell syntax and command structures
   > declare variables - <varName>='string' <varName>=1234
   > environment variables - export PATH=$PATH:/custom/path
   > expand variables - $<varName>
   > parameter expansion 
      - <varName>=${givenCommands}
   > command Substitution - executes command in subshell and replaces command 
     substitution with output, /n deleted
      - $(command)	
   > arithmetic expansion - math
      - $(( expression ))
   > substring extraction
    	
   > declare functions 
      - functionName () {}
   > for in loop 
      - for <var> in "target"; do done
      - for ((i = 0; i < "$length"; ++i)) {}

   > declare array 
      - <varName>=("item1" "item2" "item3")
      - echo "${<varName>[0]}" - print "item1"
      - echo "${<varName>[@]}" - 

   > declare associative array - typeset
      - typeset -A

   > positional parameters
      - ${1..9} 

   > special parameters
      - $# number of positional parameter
      - $@ all positional parameters (individually quoted)
      - $* all pos. params (single string)
      - $? exit status of the last command
      - $$ process id of the current shell
      - $! process id of the last background shell
      - $- current options set for the shell
      - $_ last argument of the previous shell

   > if statements
      - if [[ conditional boolean ]]; then
        elif [[ second conditional ]]; then
        fi

   > IFS - a list of characters that separate fields; used when the shell splits words as part of expansion
