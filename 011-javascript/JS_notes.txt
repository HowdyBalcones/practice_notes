Types

   - Object Types: Everything that is not a primitive type.

   + True or False
   + Generally the result of a comparison
   + Any javascript value can be converted to a boolean
   These will typically evaluate to false: 
   undefined, null, 0, -0, NaN, "" 
   + Every other value will generally convert to true. This is truthy and falsey. 
   

   - Null, undefined
   + null implies an absence of value, it is the only object of its class. 
   + also NULL, nil, or None

   and the value of function parameters where no value is passed in.

   - Immutability and Mutability ch. 3.8
   + Primitives are Immutable, it doesn't make much sense to alter their value.  
   When they are "altered" by some function or method, a new value is returned without changing the original. 
   + Objects are different from primitives. They are mutable, their values can altered directly. 
   + Two objects are not equal, even if they have the same properties and values. 
   This also holds true for arrays, even if they are the same length and contain the same values.  
   + Mutability implies that you are referring to a discrete spot in memory, that if two different variables point to the same place
   altering that memory will change both variables. 
   + Shallow and Deep copies. A shallow copy will be altered if the point of reference is altered. A deep copy is entirely
   independent from the source. I think that means it creates a separate distinct space in memory. 
   + If you want to compare two different objects for equality, you have to test their individual elements.

   - Destructuring ch. 3.10.3
   + the value of the right side of = is an array or object, and the left side is 1 or more variables that mimics the right side
   When assignment occurs, one or more of the values are extracted (destructured) from the values on the right side and 
   initialized into the variables on the left side.

   + the variables on the left do not need to match the values on the right explicitly 
   + commas can be used in the variables to skip given values on the right
   + you can pass the remaining values on the right to a single variable on the left using ...variable notation
   + This destructuring syntax can be used on objects using an iterable object ch. 12
   + any object that can be used in a for/of loop ch. 5.4.4 can also be destructured

   + expression ?. identifier 
   + expression ?.[ expression ]

   you're accessing is not already defined. 
   - They won't access the property if it is undefined or null

   - This type of evaluation behaves like a short-circuit conditional statement.

   - Logical expressions ch. 4.10
   + &&, ||, !
   AND, OR, NOT
   aka boolean algebra
   ch. 4.10.1
   + AND : may not return the associated righthand value. It checks if the leftmost value is truthy, if so then it returns the right
   side of the evaluation. 
   If the rightmost side is falsy, it returns that rightmost value without evaluating the left value. 
   This property is used in "short-circuiting" 
   if (a===b) stop();
   (a===b) && stop();
   These are equivalent. 
   So if the first value is truthy, evaluate the right side value. If the left hand value is falsey, return that left value only. 
   
   + OR ch. 4.10.2
   If one or both operands is truthy, it returns a truthy value. 
   If both operands are falsy, it returns falsy. 
   + This short circuits in a similar way to AND. 
   It evaluates from left to right. If the leftmost value evaluates to true, it returns the truthy value without checking 
   and values further to the right. If the leftmost value evaluates to false, it will check the remaining values until truthy. 
   + This can be used to create conditional values attached to a variable
   let max = maxWidth || preferences.maxWidth || 500;
   Worth noting: if 0 is valid for maxWidth, this will not work correctly since 0 will evaluate as falsy and defer to 
   preferences.maxWidth
   
   + NOT ch. 4.10.3 
   ! is a unary operator. Its purpose is to invert the boolean value of its operand. 
   + will always convert its operand to a boolean value before evaluating, meaning it will always return true or false.

   - Evaluation expressions 
   + JS has the ability to interpret strings of JS code, evaluating them to produce some value. 
   + this is done with eval()
   eval("3+2") // returns 5
   + This is powerful, but rarely used. It creates a big security risk, no user input should be passed to eval()
   This would in effect mean the user could inject arbitrary code into your program, potentially causing damage
   or leaking data in some manner. 
   Many websites will disable the eval() feature completely, because there is no sure fire way to completely sanitize
   arbitrary strings being injected into your code. 
   + its worth just not using it, or when required using it in very explicit and simple ways.

   + strict mode (ch. 5.6.3) will effect the use of eval() and eval even more. 
   It means eval cannot create new variables or functions within the calling code, it can affect state however.

   + statement blocks combine multiple statements into a single compound statement within curly braces. 
   + statement blocks don't typically end with a semicolon
   + the lines in a statement block are usually indented to show their "depth" compared to the global scope of the program. 
   
   + empty statements are used when you want to include no statement where one is expected
   uses ;
   This is occasionally applied with loops that have no body as 
   for(let i = 0; i < a.length; a[i++] = 0); // initialize an array length a
   This empty statement syntax is known to be confusing at times, and is often avoided. But can be useful for terseness. 
   
   - Conditionals ch. 5.3
   + conditionals execute or skip other statements depending on the value of a specified expression
   + often known as branches of code. 

   + if ch. 5.3.1
   + allows a javascript program to execute statements conditionally
   if (expression) 
      statement
   if (username === null) 
      username = "John Doe";
   if (!username) username = "John Doe";
   + parentheses are required around the expression
   + statement blocks can be used to evaluate a compound statement as a result of the if expression
   if (!address) {
      address = "";
      message = "Please specify an address.";
   }
   + second form of if introduces else
   if (expression) 
      statement1
   else 
      statement2
   + executes statement1 if expression evals truthy, statement2 if falsy
   + it's important to include the {} for nested expressions, because other than indentation and a strict reading of 
   the code, it is hard to spot any potential logic errors. 
   
   - else if 
   + technically there is no else if statement built into javascript, but it is a common idiom (same w/ c++)
   if (expression) {
      statement;
   } else if (expression) {
      statement;
   } else if (expression) {
      statement;
   } else {
      final statement;
   }
   + short circuits, meaning the first truthy eval will cause its given statement to run, and then ignore the remaining options. 
   + it's easier to read than nesting if statements, which can get you the same effect. 
   
   - switch ch. 5.3.3
   + if all of the branches depend on the value of a single expression, if/else becomes redundant and switches should be used. 
   switch(expression) {
      statements
   }
   switch(n) {
      case 1:
      statement
      break;
      case 2:
      statement
      break;
      case 3:
      statement
      break;
      default: // if all cases fail, use default case.
      statement
      break;
   }

   + the numbers in the above example can be strings, or even arbitrary expressions. 
   + switch statements in javascript are much less efficient than their c, c++, java counterparts. 
   So the difference between if/else and switches, in JS, is largely syntactical 
   + default can appear anywhere in the switch statement 
   
   - Loops ch. 5.4
   + loops repeat parts of a program a given number of times. 
   
   + while ch. 5.4.1
   while (expression)
      statement
   + if expression returns falsy, then the statement is skipped. Exit condition.
   + if expression returns truthy, then the statement is executed and jumps back to evaluating the expression again. 
   while (true) would be an infinite loop. Always define a stable exit condition. 
   example: 
   let count = 0;
   while (count < 10) {
      console.log(count);
      ++count;
   }
   
   + do while ch. 5.4.2
   do 
      statement
   while (expression)
   + similar to a while loop, but executes at least once. 
   + maybe useful in cases where you want to verify or test a value at least once, and if something changes test it again. 
   function printArray(a) {
      let len = a.length, i = 0;
      if (len === 0) {
         console.log("Empty Array");
      } else {
         do {
            console.log(a[i]);
         } while (++i < len);
      }
   }

   - for ch. 5.4.3
   + creates a common pattern for loops that can be more convenient than a while loop. 
   + initialization, test, and the update are each components of a for loop. They are considered separate expressions
   for (initialize; test; increment) 
      statement
      for (let count = 0; count < 10; count++) {
         console.log(count);
      }
   + the for loop is a common place for the comma operator, though not that common. 
   example: 
   let i, j, sum = 0;
   for (i = 0, j = 10; i < 10; i++, j--) {
      sum += i * j; // there is a math term for this. 
   }
   + by far the most often use of a for loop is to traverse some numeric range, though that's not required. 
   example: 
   function tail(o) {
      for (; o.next; o = o.next) ; // Traverse while o.next is truthy
      return o; 
   }
   + for (;;) // this is an infinite loop, similar to while(true);
   + if you leave out one of the three components in a for loop, the ; is still required to differentiate the remaining statements. 
   + this last above example is common for traversing nodes in a linked-list structure or something similar. 
   
   - for/of ch. 5.4.4 ES6
   + uses the for keyword, but different than a for or for/in loop. 
   + works in combination with iterable objects (ch. 12)
   + arrays, strings, sets, maps are iterable objects in JS
   example: 
   let data = [1,2,3,4,5,6,7,8,9], sum = 0;
   for (let element of data) {
      sum += element;
   }
   return sum;    // 45
   + arrays are iterated "live", as in they effect the state of your program. 
   + this above example will sum all the elements of the array. 
   + you can make this loop infinite by pushing sum onto the target array during each iteration. 
   
   + for/of on objects
   + Objects are not in and of themselves iterable. 
   + calling for of on a regular object will throw a TypeError runtime error. 
   example: 
   let o = { x: 1, y: 2, z: 3 };
   for (let element of o) { // TypeError, not inherently iterable
      console.log(element)
   }
   + iterating through a regular object is usually done with for/in
   let o = { x: 1, y: 2, z: 3 };
   let keys = "";
   for (let k of Object.keys(o)) {
      keys += k;
   } 
   return keys; // "xyz"
   
   example:
   let sum = 0;
   for (let v of Object.values(o)) {
      sum += v;
   }
   return sum; // 6

   example: 
   let pairs = "";
   for (let [k,v] of Object.entries(o)) {
      pairs += k + v;
   } 
   return pairs; // x1y2z3
   
   + for/of with strings 
   + strings are iterable character by character in JS
   let frequency = {};
   for (let letter of "mississippi") {
      if (frequency[letter]) {
         frequency[letter]++;
      } else {
         frequency[letter] = 1;
      }
   } 
   + strings are iterated bay Unicode codepoint, not UTF-16 character. 
   This would matter with emojis for example, since a string of three emojis would have a length of 6, due to the appended 
   16 bit integers to create the neccesary unicode value. 
   + for/of will run three times in this emoji example because it reads codepoints. 
   
   + for/of with Set and Map
   + the builtin Set and Map classes were added in ES6 
   example: set
   let text = "Na na na na na na na na Batman!";
   let wordSet = new Set(text.split(" "));
   let unique = [];
   for (let word of wordSet) {
      unique.push(word);
   }   
   return unique // ["Na", "na", "Batman"];
   
   example: map 
   let m = new Map([[1, "one"]]);
   for (let [key, value] of m) {
      key // 1
      value // "one"
   }
   + maps are iterated through their key:value pairs
   + each iteration returns an array of a [key, value]
   
   + asynchronous iteration with for/await ch. 12, 13 ES2018
   + this is known as an asynchronous iterator and a variant of the for/of loop
   example: 
   async function printStream(stream) {
      for await (let chunk of stream) {
         console.log(chunk);
      }
   } 
   
   - For/In
   + while for/of requires an iterable object, for/in works on any object after in
   + for/in has been part of javascript since the beginning (og)
   for (variable in object) {
      statement
   }
   for (variable in object)
      statement
   example: 
   for (let p in o) {
      console.log(o[p]); // print the value of each property
   }

   + first evaluates the object. If undefined or null, the body of the loop is skipped entirely. 
   + if not nullish, the body of the loop is executed once for each enumerable property of the object. 
   + before each iteration, the variable expression is evaluated and assigns the name of the property 
   to it (string);
   + the variable can be an arbitrary expression, as long as it evals to something suitable for the left side of an assignment. 
   example: 
   let o = { x:1, y: 2, z: 3 };
   let a = [], i = 0;
   for (a[i++] in o) ; 

   + arrays are also a specialized object in js and can be enumerated with a for/in 
   example: 
   for(let i in a) console.log(i);
   + it is worth noting, almost always want to use a for/of loop for arrays in modern JS. 
   But in a scenario like building Extendscript plugins, a for/in might be the  best tool available for a given task. 
   + ok for/in does not enumerate symbol properties of an object 
   + many properties of the builtin javascript objects are not enumerable 
   + all properties and methods defined in your code are enumerable, so custom objects and classes. 
   + inherited properties are also enumerated by for/in, which is why many programmers prefer to use a for/of loop with Object.keys()
   + if the body of a for/in loop deletes a property that has not been enumerated, they may or may not be enumerated (pg.112)(ch.6.6.1)
   
   - jump statements ch. 5.5
   + causes the interpreter to jump to a new location in the source code. 
   + break causes the interpreter to jump to the end of a loop or other statement. 
   + continue makes the interpreter skip the rest of the body of a loop and jump back to the top of a loop to begin a new iteration. 
   + JS allows statements to be labeled, and break and continue can identify the target loop or other statement label.
   + return causes the interpreter to jump from a function invocation back to the code that invoked it, and supplies the 
   value for invocation. 
   + throw iterim return from a generator function. It raises or "throws" an exception, and is designed to work with try/catch/finally
   
   - Labeled Statements ch. 5.5.1
   + any statement can be labeled 
   identifier: statement
   example: 
   mainloop: while(token !== null) {
         // some code
         continue mainloop; // jumps to the next iteration of mainloop. 
         }
   + The identifier cannot be a reserved word
   + You can use existing variable and function names. Labels and functions/variables are in different namespaces. 
   + nested statements can have the same label, but distinct statements cannot. 
   + Statements can have multiple labels. Terrifying. 

   - break ch. 5.5.2
   + causes the innermost enclosing loop or switch statement ot immediately exit
   example:
   break;
   + break is only legal inside a loop or switch
   + often used when a loop meets some condition and is no longer needed
   example: 
   for (let i = 0; i < a.length; ++i) {
      if (a[i] === target) break;
   } 
   + you can target a specific labeled jump statement 
   example: 
   break labelName;
   + This can be used to break out of an outer enclosing labeled statement
   example: 2d array or AoA
   let matrix = getData();
   let sum = 0, success = false;
   computeSum: if (matrix) {
            for (let x = 0; x < matrix.length; ++x) {
                     let row = matrix[x];
                     if (!row) break computeSum;
                     for (let y = 0; y < row.length; ++y) {
                        let cell = row[y];
                        if (isNaN(cell)) break computeSum;
                        sum += cell;
                     }
                  }
                  success = true;
            } 
     
   - continue ch. 5.5.3
   + similar to break, instead of leaving the innermost loop entirely, it restarts the loop at the next iteration. 
   example:
   continue;
   continue labelName;
   + Can only be used inside a loop body
   example: 
   for (let i = 0; i < data.length; ++i) {
      if (!data[i]) continue; 
      total += data[i];
   } // this would skip empty array cells, so you aren't trying to sum nullish values
   
   - return 5.5.4
   + return statements within a function specifies the value of invocations of that function. 
   example
   return expression;
   + must be enclosed inside a function
   + the enclosing function "returns" the value of expression to that functions caller
   + can be used without expression to return undefined. 
   example:
   function displayObject(o) {
      if (!o) return; 
   }

   - yield ch. 5.5.5, 12.4.2 ES6
   + used only in generator functions (ch. 12.3) to produce the next value in a generated sequence of values
   without actually returning.
   function* range(from, to) {
      for (let i = from; i <= to; ++i) {
         yield i;
      }
   }
   
   - throw 5.5.6 
   + an exception is a signal that an exceptional condition or error has occurred. 
   Throwing an exception is to alert the program about the error. 
   Catching an exception is what handles the condition. 
   + JS will throw an exception when there is a runtime error or if there is an explicit throw statement. 
   example: 
   throw expression;
   + expression can eval to any type.
   + Error is a class with subclasses with useful properties and methods. 
   example: 
   function factorial(x) {
      if (x < 0) throw new Error("x must not be negative"); // throws if x is negative
      let f;
      for (f = 1; x > 1; f *= x, x--) ;
      return f;
   }
   factorial(4) // 24
   + exceptions propogate up through the call stack. 
   + they will look for the nearest handler before moving up the call stack. 
   
   - try/catch/finally 5.5.7
   + try contains the block of code that is being tested. 
   + catch is invoked only if there is an exception thrown by its associated try clause. 
   + finally is optional, contains "cleanup" code that will always be executed regardless of what occurs in the try clause. 
   example: 
   try {
      // some code to run.
   } catch (e) {
      // code that will handle any exceptions in the try. 
      // e refers to the Error object
      // this block might do nothing, throw a new error, or alter the state of a program. 
   } finally {
      // This block will always run, no matter what happens in the try block. 
      // 1. normally after reaching the bottom of the block
      // 2. beecause of a break, continue, or return statement
      // 3. with an exception that is handled by a catch clause
      // 4. with an uncaught exception that is still propogating
   }
   + the value associated with the exception is passed to the parameter of the catch clause
   Usually an Error object, though not always. 
   example: 
   try {
      let n = Number(prompt("Please enter a positive integer", ""));
      let f = factorial(n);
      alert(n + "! = " + f);
   } catch (ex) {
      alert(ex);
   }
   
   + finally will execute after a catch, but if there is no catch it will run then any exceptions are passed to the 
   nearest handler. 
   + you can call just a try and finally block
   
   + bare catch clauses
   + sometimes there is an exception but its value is irrelevant 
   example: 
   function parseJSON(e) {
      try {
         return JSON.parse(s);
      } catch {
         // no parameter for catch, so we discard the value of the exception and simply return undefined
         return undefined;
      }
   }

   + runs a block of code as if the properties of the object parameter were variables in scope for that code. 
   example: 
   with (object) 
      statement
   + is forbidden in strict mode and should be considered deprecated in non-strict
   + mostly because it is difficult to optimize anything that uses with.

   example: 
   let f = document.forms[0];

   - debugger ch. 5.6.2
   + has a number of useful purposes. can be used to print variable values or examine the call stack. 
   + creates a breakpoint in the code. 
   
   - "use strict" ch. 5.6.3
   + is technically not a statement, it's considered a directive. Close enough for this textbook. 
   + the quotation is necessary. 
   + it can appear only at the start of a script or a function 
   + makes code execute in strict mode. Strict mode is a subset of language fixes that provide stronger error checking and 
   increased security. 
   + the significant differences in strict mode compared to standard JS
   1. the with statement is not allowed. 
   2. all variables must be declared. ReferenceError is thrown if you assign a value to an identifier that is not a 
   declared function, variable, function parameter, catch clause parameter, or property of the global object.
   3. functions invoked as functions rather than methods have a this value defined. 
   4. assignments to nonwritable properties and attempts to create new properties on non-extensible objects will throw a TypeError. 
   5. code passed to eval() cannot declare variables or define functions in the callers scope. 
   Variable and function definitions live in a new scope created for the eval(). This scope is discarded with the eval() returns. 
   6. SyntaxError is thrown if delete is used on a variable, function, or function parameter. 
   7. attempts to delete a nonconfigurable property throws a TypeError. 
   8. object literals cannot declare two or more properties with the same name. 
   9. functions cannot have two or more parameters with the same name. 
   10. octal integer literals are not allowed.
   11. identifiers eval and arguments are treated as keywords, meaning their value cannot be altered. This means they cannot
   be used as identifiers, declared as variables, use them in function names, parameter names, or as identifiers in catch blocks.
   12. the ability to examine the call stack is restricted. arguments.caller and arguments.callee both throw a TypeError within a 
   strict mode function. Strict mode functions also have caller and arguments properties that throw TypeError when read.

- Objects ch. 6
   + the most fundamental datatype in JS
   + composite values: it aggregates multiple values and allows you to store and retrieve those values by name. 
   + objects are unordered collections of properties, a property is a name followed by some value. 
   + property names are usually strings, though they can be Symbols. Properties map names to values. 
   + also known as hash, hash-table, dictionary, associative array and etc
   + other than being a string to value map, it inherits properties from another object known as its "prototype"
   + methods of an object are usually inherited properties. Prototypal inheritance is a major feature of JS. 
   + JS objects are dynamic, properties can be added and deleted. 
   + can be defined as static objects AKA structs
   + can be used to represent sets of strings
   + any value in JS that is not a string, number, Symbol, true, false, null, or undefined is an object. 
   + common things to do with objects is to create, set, query, delete, test, and enumerate their properties. 
   + no object may have two properties of the same name. 
   + the value may be any valid JS value, or getter and setter functions (ch. 6.10.6)  
   + it can be useful to determine between inherited and directly defined properties. 
   Use "Own Property" when this is needed. 
   + properties have attributes: 
   1. writable - whether the object can be set. 
   2. enumerable - whether the property is returned by for/in
   3. configurable - specifies if the property can be deleted and attributes altered. 
   + by default all of the objects created by the program are enumerable, writable, and configurable. 
   
   - Creating objects ch. 6.2
   + can be made with object literals, the new keyword, and with Object.create() 
   
   - object literals ch. 6.2.1
   + comma separated list of name:value pairs enclosed by {} brackets
   examples: 
   let empty = {};
   let point = { x: 0, y: 0 };
   let p2 = { x: point.x, y: point.y };
   let book = {
      "main-title": "Javascript",
      "sub-title": "The Definitive Guide",
      for: "all audiences",
      author: { firstname: "David", lastname: "Flannigan" }      
   };
   + object literals create a distinct object each time they are evaluated
   + the value of each property is evaluated each time the literal is evaluated. 
   + new object literal features are covered in ch. 6.10
   
   - creating an object with new
   + the new operator creates and initializes a new object. Keyword must be followed by a function invocation. 
   + this can be used to create a new .this instance from a prototype object. 
   + a function used in this way is called a constructor initializes the newly created object. 
   examples: 
   let o = new Object();
   let a = new Array();
   let d = new Date();
   let r = new Map();
   
   - prototypes ch. 6.2.3
   + basically every JS object will have a prototype associated with it. Objects inherit from their prototype. 
   + all objects created as Object literals will have the same prototype. 
   + objects made with new Constructor() functions inherit from the prototype property of the constructor function itself
   examples: 
   new Array() // would use the Array.prototype
   new Date() // would use the Date.prototype
   + Object.prototype doesn't have a prototype
   + most builtins will inherit from the Object.prototype
   + This inheritance from one prototype to the next is called the prototype chain (ch. 6.3.2, 9);
   
   Object.create() ch. 6.2.4
   + creates a new object, using its first arg as the prototype of that object
   examples: 
   let o1 = Object.create({ x:1, y:2 });
   o1.x + o1.y // returns 3
   + can pass null so the new object has no prototype, meaning it has no properties or methods, including builtins.
   example: 
   let o2 = Object.create(null);
   + to create an ordinary object that does builtins, pass in Object.prototype 
   example: 
   let o3 = Object.create(Object.prototype);
   + the second optional argument to Object.create is a list of properties applied to the created object. (ch. 14.1).
   + an important use of Object.create is to guard against unintended modification 
   example: 
   let o = { x: "don't change this value" };
   library.function(Object.create(o)); // guard against accidental modification
   
   - Querying and Setting Properties
   + to get the value of a property, use dot (.) or square bracket ([]) operators described in ch. 4.4
   + dot operator must be a simple identifier, square brackets can be an expression that evaluates to a property name.
   + when using dot operator, you can't use an integer value. must rely on expression notation.
   examples: 
   let author = book.author;
   let name = author.surname;
   let title = book["main title"];
   + to create or set a property use dot or bracket notation, but put them on the lefthand side of the assignment expression
   book.edition = 7;
   book["main title"] = "ECMAScript";
   + when using square bracket notation, the expression must evaluate to a string, value than can convert to a string, or a Symbol
   It is common to use numbers inside bracket notation (ch. 6.10.3) 
   
   - Objects as Associative Arrays
   + dot notation comes from C and other strongly typed languages. 
   + object["property"] notation comes from the fact that JS objects are associative arrays
   + C and other strongly typed languages must have object properties defined at runtime 
   + JS can add properties to objects all day. 
   example: 
   function addStock(portfolio, stockname, shares) {
      portfolio[stockname] = shares;
   }
   function computeValue(portfolio) {
      let total = 0.0;
      for (let stock in portfolio) {
         let shares = portfolio[stock];
         let price = getQuote(stock);
         total += shares * price;
      }
      return total;
   }
   + objects are commonly used as associative arrays
   + maps may be better suited to the task (ch. 11.1.12)
   
   - Inheritance ch. 6.3.2
   + objects in JS have a set of "own properties" and also inherit from a prototype object. 
   + if you query for a given property and the first object does not have it, if that object has a prototype, 
   then that objects prototype is queried for the same property. This proceeds up to the top level Object.prototype 
   + inheritance occurs only for querying, not for setting. That allows for selectively overriding inherited properties. 
   example: 
   let unitCircle = { r:1 };
   let c = Object.create(unitCircle);
   c.x = 1; c.y = 1;
   c.r = 2;
   unitCircle.r // returns 1, the prototype is not affected. 
   + there is one exception to the rule that a property assignment fails or creates or sets a property in the original object:
   If o1 inherits property x, and that property is an accessor property with a setter method, then that setter method is called
   rather than creating a new property x in o. 
   + That setter method is called on object o, not its prototype. 
   
   - Property Access Errors ch. 6.3.3
   + Property access expressions do not always return or set a value. 
   + No error is thrown if you query a property that does not exist. An undefined value is returned. 
   + It is an error to query an object that itself does not exist. Throws TypeError
   + property access will fail if the left side of . is null or undefined. 
   example: avoiding this
   let surname = undefined; 
   if (book) {
      if (book.author) {
         surname = book.author.surname;
      }  
   } 
   
   example: using conditional property acces (ch. 4.10.1)
   + this is also called conditional chaining
   let surname = book?.author?.surname;
   + generally property assignment fails under these conditions
   1. the given property is read only
   2. the given property is an inherited and read only
   3. the given object is non extensible, it does not have the property, its prototype chain does not have the property
   
   - Deleting Properties ch. 6.4
   + The delete operator removes a property from an object. 
   + it deletes the property itself, not the value of the property. 
   examples: 
   delete book.author;
   delete book["main title"];
   + delete operator only works on own properties
   + to delete an inherited property, it must by removed from the prototype chain.
   + returns true if the deletion was sucessful or had no effect, or if used on an expression that doesn't have properties 
   examples: 
   let o = { x: 1 };
   delete o.x // returns true
   delete o.x // returns true but does nothing
   delete o.toString // returns true, does nothing (not own property)
   delete 1 // returns true, has no effect on the value 1
   + delete cannot effect a property that have the configurable attribute set to false
   + in strict mode, all deletions of nonconfigurable properties will throw a TypeError
   + also in strict mode, delete must be specific with its property acces as delete globalThis.x
   
   - Testing Properties ch. 6.5
   + objects are unordered sets of properties. It is useful to test whether properties exist or not, if it has a given name, etc.
   + this can be done with the "in" operator, hasOwnProperty(), and propertyIsEnumerable(), or simply by querying the property. 
   + These above methods also work with symbols. 
   examples:

   - Enumerating Properties ch. 6.6

   function merge(target, ...sources) {
      for (let source of sources) {
         for (let key of Object.keys(source)) {
            if (!(key in target)) {
               target[key] = source[key];
            }
         }
      }
      return target;
   }

   - Serializing Objects ch. 6.8

   - Property Getters and Setters ch. 6.10.6 ES5
   + objects so far have been shown with data properties; a name and ordinary value. 
   + JS supports "accessor properties", not having a single value but 1 or 2 accesor methods: a getter / setter
   + when a program queries the accessor property, it runs the getter/setter method. 
   The return value is the property access expression. 
   + when the program sets the value of an accessor property, JS invokes the setter method, passing the value of the righthand 
   assignment. This method "sets" a property value in the object. The return is ignored in a setter method. 
   + If a property is a getter/setter, it is a read/write property. 
   If only a getter, it is a read only property. 
   If only a setter, it is a write only property. This is not possible with ordinary data properties. Read attempts are undefined.
   example: 
   let o = {
      dataProp: value,
      get accessorProp() { return this.dataProp; }.      // getter
      set accessorProp(value) { this.dataProp = value; } // setter
   };
   
   let p = {
      x: 1.0,
      y: 1.0,
      get r() { return Math.hypot(this.x, this.y); },
      set r(newValue) {
        let oldValue = Math.hypot(this.x, this.y);
        let ratio = newValue/oldValue;
        this.x *= ratio;
        this.y *= ratio; 
      },
      get theta() { return Math.atan(this.y, this.x); }
   };
   p.r     // Math.SQRT2
   p.theta // Math.PI / 4
   
   + .this keyword invokes these functions as methods of the object they are defined on, in the above case meaning x, y 
   + Accessor properties are inherited, so the defined object can be used as a prototype for other objects. 
   + these aren't quite classes yet, there is no built in constructor function 
   example: 
   let q = Object.create(p);
   q.x = 3; q.y = 4;
   q.r      // returns 5
   q.theta  // returns Math.atan(4, 3);
   
   + another use of this is to ensure the object conforms to a certain behavior
   example:
   const serialNum = {
      _n: 0,
      get next() { return this._n++ },
      set next(n) {
         if (n > this._n) this._n = n;
         else throw new Error("serial num. can only be set to a larger value");
      }
   };
   serialNum.next = 10;    // set the starting num
   serialNum.next;         // 10
   serialNum.next;         // 11 ; different each time the program invokes next
   
   + "magic behavior" properties
   example: 
   const random = {
      get octet() { return Math.floor(Math.random()*256); },
      get uint16() { return Math.floor(Math.random()*65536); },
      get int16() { return Math.floor(Math.random()*65536)-32786; }
   };
   + these properties will return a random number when invoked.

   - Array Iterator Methods ch. 7.8.1
      > iterate over arrays, passing elements to a supplied function. 
      Convenient for iteration, mapping, filters, tests, and reductions
      > Generalizations about the following methods: 
      accept a function as their first argument, invoke said function once for each element of the referenced array. 
      If the array is sparse, the function is not called on the empty indice. 
      In most cases, the specified function is called with three args
         1. the value of the array element 
         2. the index of the array element 
         3. and the array itself 
         Usually will not need more than the first argument
      Most of the iterator methods will take a second argument, which becomes .this inside of the specified function. 
      None of the methods below will modify the array in and of themselves, but the function passed in can. 
   
   + array.forEach() 
   example: 
      let data = [1,2,3,4,5], sum = 0; 
      data.forEach(value  => { sum += value; }); // returns 15
      data.forEach(function (v, i, a) { a[i] = v + 1; }); // data === [2,3,4,5,6]
      // the v, i, a parameters are the value, index, and array variables respectively. 
      + for each does not provide a means for terminating early on its own. There is no equivalent to a break statement.

      > passes in each element of the array to the specified function, returning an array of the altered values. 
   example: 
      let a = [1,2,3];
      a.map(x => x*x); // returns [1, 4, 9]
      + Does not modify the array called upon
      + If the array is sparse, the function will not be called for missing elements, but the returned array will be 
      sparse in the same way as the original. Same length and same missing elements. 
   
   + array.filter() 
      > returns an array containing a subset of elements from the invoked array.
      > the passed in function should be a predicate: a function that returns true or false. 
      > The predicate is invoked just as forEach() and map(). If the return is true or a value that converts to true, 
      then the element passed to the predicate is a member of the subset and is added to returned array. 
   example: 
      let a = [5,4,3,2,1];
      a.filter(x => x < 3)    // [2,1] values less than three
      a.filter((x, i) => i%2 === 0) // [5,3,1] every other value
      + filter skips missing elements and always returns dense arrays. 
      example: closing gaps in sparse arrays 
      let dense = sparse.filter(() => true);
      // to close gaps and remove nullish elements
      a = a.filter(x => x !== undefined && x !== null);
   
   + array.find() and array.findIndex() 
      > like .filter in they iterate through an array looking for elements your predicate function returns a truthy value on. 
      > These methods stop iterating the first time the predicate returns a truthy value. 
      > Find returns the element, findIndex returns the index. 
      > If no element returns truthy, find() returns undefined and findIndex() return -1
   example: 
      let a = [1,2,3,4,5];
      a.findIndex(x => x === 3); // 2 
      a.findIndex(x => x < 0); // -1 no negative numbers in the array
      a.find(x => x % 5 === 0);  // 5, a multiple of 5 (nice)
      a.find(x => x % 7 === 0); // undefined, no multiples of 7 in the array 
   
   + array.every() and array.some() 
      > these are array predicates 
      > .every() method is like the "for all" quantifier in math. It returns true if and only if the predicate function returns
      true for every element in the array. 
   example: 
      let a = [1,2,3,4,5];
      a.every(x => x < 10);      // true
      a.every(x => x % 2 === 0); // false, there are odd numbers
      + .some() is like the "there exists" quantifier in math. It returns true if there exists at least one element in the array 
      for which the predicate returns true. It returns false if and only if the predicate returns false for every element. 
      a.some(x => x%2 === 0); // true, there are some even numbers
      a.some(isNaN)           // false, there are no non-numbers
      + both of these methods return as soon as they know what value to give. 
      + every() returns true and some() returns false on empty arrays. 
   
   + reduce() and reduceRight() 
   + combines the elements of the array according to the provided function. 
   + also known as inject and fold. Used in functional style programming often. 

   + array.reduce() takes two args: the provided function, and an initial value to pass to that function. 
      > functions used with reduce() are different than forEach() or map(). The usual value, index, array
      arguments are now the 2nd, 3rd, and 4th arguments. The first is an accumulator that stores the value of the reduction so far. 
      > if called on an empty array, throws a TypeError. On an array of just 1 value, it will return that value without 
      running the supplied function. 
   examples:

      a.reduce((x,y) => x+y, 0);          // returns 15, sum of numbers
      a.reduce((x,y) => x*y, 1);          // returns 120, product of numbers
      a.reduce((x,y) => (x > y) ? x : y); // 5, largest of the values in a

      > works similarly to reduce(), except it processes the array from highest to lowest index values.

   + .shift() and .unshift() are similar to push() and pop() but alter the first element in the array. 
      > unshift() can pass multiple arguments at once in a comma delimited list, and they are added all at once rather than 
      one at a time. This means it could effect the order they are placed in. 
   + Both are less efficient than pop() and push() because each element in the array must have its index iterated after a shift.
   
   - Subarrays with slice(), splice(), fill(), and copyWithin() 
   + these methods are used to create subarrays of continguous regions in the referenced array. 
   
   + slice() 
      > takes two arguments, the start and ending index that is to be returned. 
      > contains the first element specified, up to but not including the final element specified. 
      > if no second element is specified, it returns the starting element to the end of the array. 
      > if a negative first arg is passed in, it is relative to the length of the array. It will count from the end to the start. 
      > does not modify the array on which it is invoked. 
   example: 
      let a = [1,2,3,4,5];
      a.slice(0,3);        // returns [1,2,3];
      a.slice(3);          // returns [4,5];
      a.slice(1,-1);       // returns [2,3,4];
      a.slice(-3, 2);      // returns [3];
   
    + splice() 
      > modifies the array on which it is invoked. 
      > general purpose method for inserting and removing elements. 
      > Can insert and remove elements at the same time, or one or the other. 
      > first arg is where splice() is to begin (index)
      > second arg is the amount of elements that are to be removed. If omitted, then all elements from start to end are removed.
      > every argument after the first two will specify what is being inserted into the array. They are inserted from first to last. 
      This is a convenient place for the ... spread operator to pass in a list of elements. 
      > returns an array of the deleted elements, or an empty array if no elements were deleted. 
      > arrays are inserted whole, without flattening of any kind. 
    example: 
      let a = [1,2,3,4,5,6,7,8];
      a.splice(4);               // returns [5,6,7,8] and a is now [1,2,3,4];
      a.splice(1,2)              // returns [2,3] and a is [1,4];
      a.splice(1,1)              // returns [4] and a is [1];
      
   
   + fill()
      > sets the elements of an array, or slice of an array, to a specific value. 
      > mutates the referenced array, and returns the modified array. 
      > first arg is a value to set array elements to. 
      > optional second arg specifies the starting index. 
      > optional third arg specifies the ending index. Elements up to but not including the specified end index. 
      > negative numbers work as they do in slice() 
   example: 
      let a = new Array(5);
      a.fill(0)               // dense array of 0's
      a.fill(9, 1)            // [0,9,9,9,9]
      a.fill(8,2,-1)          // [0,9,8,8,9]
   
   + copyWithin() 
      > copies a slice of the referenced array to a new position within that array. 
      > modifies the array in place and returns the modified array, but will not change the length of the array. 
      > first arg specifies the destination index of the first element to be copied. 
      > second arg specifies the index of the first copied element. If omitted, 0 is used. 
      > third arg specifies the end of the slice of elements being copied. If omitted, the length of the array is used. 
      Elements from the start index, up to but not including the last element, will be copied. 
      > You can use negative numbers as in slice()
      > Intended to be a high performance method that is useful with typed arrays (ch. 11.2) similar to memmove() from 
      the C standard lib.
      > Will work correctly even if there is overlap in the designated regions.
   example: 
      let a = [1,2,3,4,5];
      a.copyWithin(1);        // [1,1,2,3,4] copy array elements up to 1
      a.copyWithin(2,3,5);    // [1,1,3,4,4] copy last 2 elements to index 2
      a.copyWithin(0, -2);    // [4,4,3,4,4] negative offsets work as well
   
   - Array Searching and Sorting methods ch. 7.8.6

   + indexOf() and lastIndexOf() 
      > both search an array for an element with a specified value and return the index of the first such element found. 
      > returns -1 if no matching element was found. 
      > indexOf() searches from start to end
      > lastIndexOf() searches from end to start. 
      > the first arg for both is the element which is being searched for
      > optional second arg specifies the index which to begin searching from. 
      > negative indices are permitted as in slice()
   example: 
      // this will search an array and return an array of all matches
   function findall(a, x) {
      let results = [], len = a.length, pos = 0;
      while(pos < len) {
         pos = a.indexOf(x, pos);
         if (pos === -1) break;
         results.push(pos);
         pos = pos + 1;
      }
      return results;
   }
   
   + includes() ES2016
      > takes a single argument, returns true if the array contains that value or false if otherwise. 
      > does not tell you the index of the value, only if it exists. 
      > also known as "set membership" test. Arrays are not true sets, so use a set if that's what is required. 
      > uses strict equality for evaluation, so differently typed elements compared to your search term will be ignored. 
      > this method does consider NaN equal to itself, normally this is not the case with strict equality. 
   example: 
      let a = [1,true,3,NaN];
      a.includes(true)     // true
      a.includes(2)        // false
      a.includes(NaN)      // true
      a.indexOf(NaN)       // false, returns -1 because indexOf does not eval NaN as equal to itself

   + sort()
      > sorts the elements of the referenced array in place and returns the sorted array. 
      > when called with no args, sorts alphabetically, converting elements to strings temporarily if necessary. 
      > places undefined elements at the end of the array
      > to sort in some manner other than alphabetically, must pass a comparison function as an argument to sort()
      This function should decide which of its two args should come first in the sorted array. 
      If the first arg should come before the second, the comparison func should return a less than zero int
      If the first arg should come after the second, the comparison func should return a number greater than 0
      If both args are equivalent, then the comparison func should return 0. 
      > worth writing and understanding comparator function further if necessary. 
   example: 
      // sorting values according to numerical value
      let a = [33,4,1111,222];
      a.sort();                  // a === [1111, 222, 33, 4] alphabetical
      a.sort(function(a,b) {     // pass a comparator function, returning < 0, > 0, or 0 depending on value
         return a-b;
      });                        // returns a === [4, 33, 222, 1111] or numerical order
      a.sort((a,b) => b-a);      // returns a === [1111, 222, 33, 4] or reverse numerical order

      // sorting case-insensitive values 
      let a = ["ant", "Bug", "cat", "Dog"];
      a.sort(); // Bug and Dog appear before ant and cat
      a.sort(function(s,t) {
         let a = s.toLowerCase();
         let b = t.toLowerCase();
         if (a < b) return -1;
         if (a > b) return 1;
         return 0;
      });                        // a == ["ant", "Bug", "cat", "Dog"];
      
   + reverse() 
      > reverses the order of elements in the referenced array and returns the reversed array. 
      > Operates in place, mutating the array.

          o.length >= 0 &&                 // o.length is non-negative

   - Arrow Functions ch. 8.1.3 ES6
      > function keyword and name are omitted, as these are func expressions rather than statements
      > if the body of the arrow func is a single return statement, the curly braces can be omitted
      > if the arrow func has exactly one parameter the parenthesis can be omitted
      > if there are no args for the arrow func then empty parenthesis must be included
      > don't add new lines inbetween the parameters and => arrow. 
      > if the body of the arrow func is a single return statement but the expression to be returned is an object literal,
      the the object must be enclosed by curly braces to avoid syntactic ambiguity. 
      > this arrow func syntax is often used when passing one function to another, a common occurrence with methods like array.map() or array.filter()
      > arrow func inherit the .this value from the environment in which they are defined, rather than
      defining their own invocation context as functions defined in other ways do. 
      > arrow functions do not inherit a prototype property, which means they cannot be used as a constructor function for new classes (ch. 9.2)      
   examples:

      const sum = (x,y) => x + y;
      const polynomial = x => x*x + 2*x + 3;

      const g = x => ({ value: x });            // valid, returns object
      const h = x => { value: x };              // technically valid but h() returns nothing here
      const i = x => { v: x, w:x };             // invalid, throws syntax error

      let squares = [1,2,3,4].map(x => x*x);                   // squares == [1,4,9,16];

   - Invoking Functions ch. 8.2
   + JS code is not run when defined within the body of a function. It is only run once that function is invoked. 
   + JS functions are invoked in five different ways: 
      1. as functions
      2. as methods
      3. as constructors
      4. indirectly through their call() and apply() methods
      5. implicitly, via JS language features that do not appear like normal function invocations. 

   - Function Invocation ch. 8.2.1
      > functions are invoked as functions or methods with an invocation expression. 
      > invocation expressions consist of a function expression that evaluates to a function object followed by an open parenthesis, 
      a comma separated list of zero or more argument expressions, and a closing parenthesis. 
      > if the function expr. is a property-access expr., it is a method invocation. 
      > in an invocation, each arg. expr. is evaluated and the resulting values become args for the func. These values are assigned to
      the parameters named in the func. definition. 
      > In the body of the function, a param. reference evals to the corresponding argument value
      > for normal function invocation, the return value becomes the value of the function expression.
      > Conditional Invocation: ES2020
      .? can be inserted after the function expression and before the open parenthesis in a function invocation
      in order to invoke the function only if it is not nullish. 
      > for function invocation in non-strict mode, the invocation context (.this value) is the global object. 
      In strict mode, the invocation context is undefined. 
      Functions defined using the arrow syntax behave differently, they always inherit the .this value that is in effect where they are defined. 
      > when calling recursive functions, it is important to remember the call stack. Each time a function is invoked, it is pushed onto the stack. 
      When it finishes running, it is popped off the stack. This stack adds to the memory overhead of a program. 
   example:
      printprops({x:1});                                            // the return values of these function invocations are assigned to variables
      let total = distance(0,0,2,1) + distance(2,1,3,5);
      let probability = factorial(5)/factorial(13);
      f?.(x) == (f !== null && f !== undefined) ? f(x) : undefined; // these are both equivalent statements. 

   - Method invocation ch. 8.2.2
      > methods are just function that are stored as a property of some object. 
      > Given function f and object o, a method m of o can be defined as: o.m = f;
      > methods are invoked the same way as typical functions, but their invocation context is what differs. 
      Property access expressions consist of two parts: an object reference, and a property name. 
      In a method-invocation, the object becomes the invocation context, and the function body can refer to that object by using .this
      > most methods use dot notation for invocation, but property access notation object[expression] also cause method invocation
      > there is a subjective elegance to using method invocation syntax over typical functional syntax. Personally, both are clear to me.

      > if a nested function (that is not an arrow function) is invoked as a method, its .this value is the object it was invoked on.

      It is common to mistakenly assume a nested function within an object method will return that objects .this value.

   - Rest Parameters and Variable-Length Argument Lists ch. 8.3.2 ES6
      > Parameter default expressions enable functions to be invoked with fewer arguments than parameters. 
      > Rest parameters enable the opposite: arbitrarily more arguments than parameters. 
      > rest parameter is preceded by ... and it must be the last parameter in the function declaration.

      > within the body of the function, the rest parameter is an array. The array may be empty but will never be undefined by default.

      > because of its syntactic context the ...rest parameter is not the same as the ...spread parameter (ch. 8.3.4)

         let maxValue = first;
         for (let n of rest) {
            if (n > maxValue) {
               maxValue = n;
            }
         }
         return maxValue;
      }

   - Classes and Constructors ch. 9.2 
      > the above method is a simple means to construct a class, but not the idiomatic way. It is a factory function that creates a new instance of 
      an object with arguments passed into property values and internal methods defined in the Range object. 
      > A typical class will have a constructor. 
      > A constructor is a function designed for the initilization of newly created objects. Constructors are invoked using the new keyword (ch. 8.2.3)
      > constructor invocation automatically create the new object, so the constructor itself only needs to initialize the state of the new object. 
      > Important: constructor invocations have a prototype, and this is what is used as the prototype of the new object. 
      > While almost all objects have a property, only a few have prototype properties. 
      These are known as function objects that have a prototype property. This means that all objects created with the same constructor function
      inherit from the same object and are therefore members of the same class. 
      > Older JS code won't have the class keyword, and there are idiomatic ways of defining classes in this syntax. It also helps understand new syntax.
      > 9.1 example demonstrates how to use a factory function, whereas 9.2 demonstrates using a constructor function instead. 
      9.2 is also an example of how to define classes in older JS syntax. 
      > by convention constructors start with a capital letter, and regular functions are lowercase. 
      > factory functions use typical function invocation, whereas constructors use the new keyword or constructor invocation
      > because of Range() being called with new, it does not call Object.create(), or take any action to create a new object. 
      The new object is automatically created before the constructor is called, and it is accessible as the this value.
      new Range() simply initializes this. 
      > Constructors don't even need to explicitly return the new object. Constructor invocation does these things automatically: 
         1. creates a new object
         2. invokes the constructor as a method of that object
         3. returns the new object. 
      > within a function body, a contructor invocation can be distinguished by using new.target. If the value of that expression is defined, then
      the function was invoked as a constructor using the new keyword. This effects subclasses (ch. 9.5) b/c new.target is not always a reference 
      to the constructor it is used in. It might refer to the constructor function of a subclass. 
      If new.target is undefined, then the containing function was invoked as a function without the new keyword. 
      > JS's various error constructors can be invoked without new, this can be emulated in custom constructors
      > the above technique is only applicable to the classic style of constructors in JS, constructors made with the Class keyword require new. 
      > in 9.1, the prototype was range.methods, an arbitrary name that is descriptive. 
      in 9.2, the prototype is Range.prototype, which is mandatory. Any invocation of Range() constructor automatically uses this Range.prototype
      as the prototype of the new range object. 
      > neither implementation uses arrow functions, because they strip the prototype property from the function and cannot be constructors. 
      They also inherit this from the context which they are defined in, rather than the object through which they are invoked. This makes them
      useless for methods because the defining characteristic of methods is that they use this to refer to the instance on which they are invoked.

   - Constructors, Class Identity, and instanceof 
      > the prototype object is fundamental to the identity of a class: two objects are of the same class only if they inherit from the same prototype. 
      > The constructor that initializes the state of the new object is not fundamental: two constructor functions may have prototype properties 
      that point to the same Prototype Object. In that case both constructors can be used to create instances of the same class. 
      > a constructor serves as the "face" of a class. 
      > instanceof checks the prototype of an object, not the constructor used to create that object. 
      > to check the constructor, can use the isPrototypeOf() method
   examples: 
      r instanceof Range // returns true, r inherits from Range.prototype
      object_to_test instanceof class_to_check_for // returns boolean; the syntax for instanceof  
      function Strange() {}
      Strange.prototype = Range.prototype;
      new Strange() instanceof Range   // returns true
      range.methods.isPrototypeOf(r)   // range.methods is the prototype object from 9.1, so this is true
      
   - The constructor property ch. 9.2.2
      > in example 9.2, Range.prototype was set to a new object that contained the methods for our class. 
      While convenient, it was not neccesary to return a new object literal containing those methods. 
      > Any regular JS function (!arrow, async, or generator functions) can be used as a constructor. 
      > Constructor invocations need a prototype property.
      > This all means every regular JS function will automatically have a prototype property. 
      The value of this property is an object that has a single, non-enumerable constructor property. 
      The value of the constructor property is the function object. 
      > the constructor is inherited by the prototype, but all this constructor does is refer to the new instance of said prototype. 
      
   example: 
      let F = function {};    // function object
      let p = F.prototype;    // This is the prototype object associated with F
      let c = p.constructor;  // this is the function associated with the prototype 
      c === F                 // returns true; F.prototype.constructor === F for any F
      let o = new F();
      o.constructor === F // returns true, the constructor property specifies the class.
