   - Immutability and Mutability ch. 3.8
   + Primitives are Immutable, it doesn't make much sense to alter their value.  
   When they are "altered" by some function or method, a new value is returned without changing the original. 
   + Objects are different from primitives. They are mutable, their values can altered directly. 
   + Two objects are not equal, even if they have the same properties and values. 
   This also holds true for arrays, even if they are the same length and contain the same values.  
   + Mutability implies that you are referring to a discrete spot in memory, that if two different variables point to the same place
   altering that memory will change both variables. 
   + Shallow and Deep copies. A shallow copy will be altered if the point of reference is altered. A deep copy is entirely
   independent from the source. I think that means it creates a separate distinct space in memory. 
   + If you want to compare two different objects for equality, you have to test their individual elements.

   - Destructuring ch. 3.10.3
   + the value of the right side of = is an array or object, and the left side is 1 or more variables that mimics the right side
   When assignment occurs, one or more of the values are extracted (destructured) from the values on the right side and

   - Logical expressions ch. 4.10
   + &&, ||, !
   AND, OR, NOT
   aka boolean algebra
   ch. 4.10.1
   + AND : may not return the associated righthand value. It checks if the leftmost value is truthy, if so then it returns the right
   side of the evaluation. 
   If the rightmost side is falsy, it returns that rightmost value without evaluating the left value. 
   This property is used in "short-circuiting" 
   if (a===b) stop();
   (a===b) && stop();
   These are equivalent. 
   So if the first value is truthy, evaluate the right side value. If the left hand value is falsey, return that left value only. 
   
   + OR ch. 4.10.2
   If one or both operands is truthy, it returns a truthy value. 
   If both operands are falsy, it returns falsy. 
   + This short circuits in a similar way to AND. 
   It evaluates from left to right. If the leftmost value evaluates to true, it returns the truthy value without checking 
   and values further to the right. If the leftmost value evaluates to false, it will check the remaining values until truthy. 
   + This can be used to create conditional values attached to a variable
   let max = maxWidth || preferences.maxWidth || 500;
   Worth noting: if 0 is valid for maxWidth, this will not work correctly since 0 will evaluate as falsy and defer to 
   preferences.maxWidth
   
   + NOT ch. 4.10.3 
   ! is a unary operator. Its purpose is to invert the boolean value of its operand. 
   + will always convert its operand to a boolean value before evaluating, meaning it will always return true or false.

   + JS has the ability to interpret strings of JS code, evaluating them to produce some value. 
   + this is done with eval()

   + This is powerful, but rarely used. It creates a big security risk, no user input should be passed to eval()

   arbitrary strings being injected into your code.

   + strict mode (ch. 5.6.3) will effect the use of eval() and eval even more.

   + statement blocks combine multiple statements into a single compound statement within curly braces. 
   + statement blocks don't typically end with a semicolon
   + the lines in a statement block are usually indented to show their "depth" compared to the global scope of the program. 
   
   + empty statements are used when you want to include no statement where one is expected
   uses ;
   This is occasionally applied with loops that have no body as 
   for(let i = 0; i < a.length; a[i++] = 0); // initialize an array length a
   This empty statement syntax is known to be confusing at times, and is often avoided. But can be useful for terseness. 
   
   - Conditionals ch. 5.3
   + conditionals execute or skip other statements depending on the value of a specified expression
   + often known as branches of code. 

   + if ch. 5.3.1
   + allows a javascript program to execute statements conditionally
   if (expression) 
      statement
   if (username === null) 
      username = "John Doe";
   if (!username) username = "John Doe";
   + parentheses are required around the expression
   + statement blocks can be used to evaluate a compound statement as a result of the if expression
   if (!address) {
      address = "";
      message = "Please specify an address.";
   }
   + second form of if introduces else
   if (expression) 
      statement1
   else 
      statement2
   + executes statement1 if expression evals truthy, statement2 if falsy
   + it's important to include the {} for nested expressions, because other than indentation and a strict reading of 
   the code, it is hard to spot any potential logic errors. 
   
   - else if 
   + technically there is no else if statement built into javascript, but it is a common idiom (same w/ c++)
   if (expression) {
      statement 
   } else if (expression) {
      statement
   } else if (expression) {
      statement
   } 
   + short circuits, meaning the first truthy eval will cause its given statement to run, and then ignore the remaining options. 
   + it's easier to read than nesting if statements, which can get you the same effect. 
   
   - switch ch. 5.3.3
   + if all of the branches depend on the value of a single expression, if/else becomes redundant and switches should be used. 
   switch(expression) {
      statements
   }
   switch(n) {
      case 1:
      statement
      break;
      case 2:
      statement
      break;
      case 3:
      statement
      break;
      default: // if all cases fail, use default case.
      statement
      break;
   }

   + the numbers in the above example can be strings, or even arbitrary expressions. 
   + switch statements in javascript are much less efficient than their c, c++, java counterparts. 
   So the difference between if/else and switches, in JS, is largely syntactical 
   + default can appear anywhere in the switch statement 
   
   - Loops ch. 5.4
   + loops repeat parts of a program a given number of times. 
   
   + while ch. 5.4.1
   while (expression)
      statement
   + if expression returns falsy, then the statement is skipped. Exit condition.
   + if expression returns truthy, then the statement is executed and jumps back to evaluating the expression again. 
   while (true) would be an infinite loop. Always define a stable exit condition. 
   example: 
   let count = 0;
   while (count < 10) {
      console.log(count);
      ++count;
   }
   
   + do while ch. 5.4.2
   do 
      statement
   while (expression)
   + similar to a while loop, but executes at least once. 
   + maybe useful in cases where you want to verify or test a value at least once, and if something changes test it again. 
   function printArray(a) {
      let len = a.length, i = 0;
      if (len === 0) {
         console.log("Empty Array");
      } else {
         do {
            console.log(a[i]);
         } while (++i < len);
      }
   }

   - for ch. 5.4.3
   + creates a common pattern for loops that can be more convenient than a while loop. 
   + initialization, test, and the update are each components of a for loop. They are considered separate expressions
   for (initialize; test; increment) 
      statement
      for (let count = 0; count < 10; count++) {
         console.log(count);
      }
   + the for loop is a common place for the comma operator, though not that common. 
   example: 
   let i, j, sum = 0;
   for (i = 0, j = 10; i < 10; i++, j--) {
      sum += i * j; // there is a math term for this. 
   }
   + by far the most often use of a for loop is to traverse some numeric range, though that's not required. 
   example: 
   function tail(o) {
      for (; o.next; o = o.next) ; // Traverse while o.next is truthy
      return o; 
   }
   + for (;;) // this is an infinite loop, similar to while(true);
   + if you leave out one of the three components in a for loop, the ; is still required to differentiate the remaining statements. 
   + this last above example is common for traversing nodes in a linked-list structure or something similar. 
   
   - for/of ch. 5.4.4 ES6
   + uses the for keyword, but different than a for or for/in loop. 
   + works in combination with iterable objects (ch. 12)
   + arrays, strings, sets, maps are iterable objects in JS
   example: 
   let data = [1,2,3,4,5,6,7,8,9], sum = 0;
   for (let element of data) {
      sum += element;
   }
   return sum;    // 45
   + arrays are iterated "live", as in they effect the state of your program. 
   + this above example will sum all the elements of the array. 
   + you can make this loop infinite by pushing sum onto the target array during each iteration. 
   
   + for/of on objects
   + Objects are not in and of themselves iterable. 
   + calling for of on a regular object will throw a TypeError runtime error. 
   example: 
   let o = { x: 1, y: 2, z: 3 };
   for (let element of o) {
      console.log(element)
   }
   + iterating through a regular object is usually done with for/in
   let o = { x: 1, y: 2, z: 3 };
   let keys = "";
   for (let k of Object.keys(o)) {
      keys += k;
   } 
   return keys; // "xyz"
   
   example:
   let sum = 0;
   for (let v of Object.values(o)) {
      sum += v;
   }
   return sum; // 6

   example: 
   let pairs = "";
   for (let [k,v] of Object.entries(o)) {
      pairs += k + v;
   } 
   return pairs; // x1y2z3
   
   + for/of with strings 
   + strings are iterable character by character in JS
   let frequency = {};
   for (let letter of "mississippi") {
      if (frequency[letter]) {
         frequency[letter]++;
      } else {
         frequency[letter] = 1;
      }
   } 
   + strings are iterated bay Unicode codepoint, not UTF-16 character. 
   This would matter with emojis for example, since a string of three emojis would have a length of 6, due to the appended 
   16 bit integers to create the neccesary unicode value. 
   + for/of will run three times in this emoji example because it reads codepoints. 
   
   + for/of with Set and Map
   + the builtin Set and Map classes were added in ES6 
   example: set
   let text = "Na na na na na na na na Batman!";
   let wordSet = new Set(text.split(" "));
   let unique = [];
   for (let word of wordSet) {
      unique.push(word);
   }   
   return unique // ["Na", "na", "Batman"];
   
   example: map 
   let m = new Map([[1, "one"]]);
   for (let [key, value] of m) {
      key // 1
      value // "one"
   }
   + maps are iterated through their key:value pairs
   + each iteration returns an array of a [key, value]
   
   + asynchronous iteration with for/await ch. 12, 13 ES2018
   + this is known as an asynchronous iterator and a variant of the for/of loop
   example: 
   async function printStream(stream) {
      for await (let chunk of stream) {
         console.log(chunk);
      }
   } 
   
   - For/In
   + while for/of requires an iterable object, for/in works on any object after in
   + for/in has been part of javascript since the beginning (og)
   for (variable in object) {
      statement
   }
   for (variable in object)
      statement
   example: 
   for (let p in o) {
      console.log(o[p]); // print the value of each property
   }

   + first evaluates the object. If undefined or null, the body of the loop is skipped entirely. 
   + if not nullish, the body of the loop is executed once for each enumerable property of the object. 
   + before each iteration, the variable expression is evaluated and assigns the name of the property 
   to it (string);
   + the variable can be an arbitrary expression, as long as it evals to something suitable for the left side of an assignment. 
   example: 
   let o = { x:1, y: 2, z: 3 };
   let a = [], i = 0;
   for (a[i++] in o) ; 

   + arrays are also a specialized object in js and can be enumerated with a for/in 
   example: 
   for(let i in a) console.log(i);
   + it is worth noting, almost always want to use a for/of loop for arrays in modern JS. 
   But in a scenario like building Extendscript plugins, a for/in might be the  best tool available for a given task. 
   + ok for/in does not enumerate symbol properties of an object 
   + many properties of the builtin javascript objects are not enumerable 
   + all properties and methods defined in your code are enumerable, so custom objects and classes. 
   + inherited properties are also enumerated by for/in, which is why many programmers prefer to use a for/of loop with Object.keys()
   + if the body of a for/in loop deletes a property that has not been enumerated, they may or may not be enumerated (pg.112)(ch.6.6.1)
   
   - jump statements ch. 5.5
   + causes the interpreter to jump to a new location in the source code. 
   + break causes the interpreter to jump to the end of a loop or other statement. 
   + continue makes the interpreter skip the rest of the body of a loop and jump back to the top of a loop to begin a new iteration. 
   + JS allows statements to be labeled, and break and continue can identify the target loop or other statement label.
   + return causes the interpreter to jump from a function invocation back to the code that invoked it, and supplies the 
   value for invocation. 
   + throw iterim return from a generator function. It raises or "throws" an exception, and is designed to work with try/catch/finally
   
   - Labeled Statements ch. 5.5.1
   + any statement can be labeled 
   identifier: statement
   example: 
   mainloop: while(token !== null) {
         // some code
         continue mainloop; // jumps to the next iteration of mainloop. 
         }
   + The identifier cannot be a reserved word
   + You can use existing variable and function names. Labels and functions/variables are in different namespaces. 
   + nested statements can have the same label, but distinct statements cannot. 
   + Statements can have multiple labels. Terrifying.
